# Garaggio — working notes

A Pokémon Go-style car collecting game. Players scan real cars with the
camera, the card lands in their Collection, the CarDex records the model, and
they race over a quarter mile and rank cars on weekly Showcase boards.

This repository is the **web v1**. The eventual target is React Native + Expo,
which is why the rules live in plain functions with no React in them.

## Stack

- Next.js 16 (App Router) + React 19 + TypeScript
- Tailwind CSS v4 (theme tokens in `src/app/globals.css`, not a config file)
- Supabase for auth and data, with a browser-storage fallback
- No test framework yet

## Rules of the house

- **Scanner and catalog stay separate.** Recognition answers "which model is
  this"; the catalog answers "what is that model". A card stores what was seen
  (model, colour, place), never specs — so correcting a spec fixes every card
  at once.
- **Quarter-mile times are computed, never stored.** `performance.ts` derives
  them from power, weight and drivetrain. That is what makes a turbo matter.
- **Game rules go in `src/lib/game/*` as pure functions.** No React, no
  storage, no fetches. `src/state/game.tsx` is the only place that mutates
  player state, and the only place that knows about the store.
- **Both dictionaries or neither.** `src/lib/i18n/en.ts` is the source of
  truth; `zh.ts` is typed against it, so a missing key is a type error. Never
  put user-facing English in a component.
- **Pay attention to fair play.** Performance parts are won by racing and are
  never for sale; paid items are cosmetic. If a change would let money buy
  speed, it is wrong.
- **Privacy in the UI.** Scan locations show city and country only. Garage
  cars never show a location at all.

## Things that will bite

- Next 16 prerenders client components, so `new Date()` (and anything else
  that differs per visit) during render fails the build. Read it in an effect
  or an event handler.
- The repo's ESLint setup errors on `setState` called synchronously inside an
  effect and on reading a ref during render. Both have come up already — the
  i18n locale uses `useSyncExternalStore`, and the camera uses `.then` rather
  than `await` so the state change sits in a callback.
- `getUserMedia` never settles in some embedded browsers when capture is
  blocked by policy. Always go through `requestCameraStream` in
  `lib/game/camera.ts`, which times out.
- `AGENTS.md` is regenerated by `next dev`; leave it alone.

## Checks before calling something done

```bash
npx tsc --noEmit && npm run lint && npm run build
```
